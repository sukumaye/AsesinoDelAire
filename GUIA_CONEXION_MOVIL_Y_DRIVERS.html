2. 📱 Checklist Obligatorio para Móviles Xiaomi / Redmi (MIUI / HyperOS)

Los teléfonos Xiaomi / Redmi tienen una capa de seguridad adicional que bloquea ADB por defecto a menos que se activen tres interruptores específicos:

1
Activar Opciones de desarrollador: Ve a Ajustes > Acerca del teléfono y pulsa 7 veces seguidas sobre «Versión de MIUI» o «Versión de SO» hasta que aparezca el aviso «¡Ya eres desarrollador!».
2
Entrar a Opciones de Desarrollador: Ve a Ajustes > Ajustes adicionales > Opciones de desarrollador.
3
Activar Depuración USB: Enciende el interruptor «Depuración USB».
4
Activar Seguridad de Xiaomi: Enciende también «Instalar vía USB» y «Depuración USB (Ajustes de seguridad)» (necesario para permitir que Unity instale juegos).
5
Conectar por USB: Conecta el cable al PC y selecciona «Transferencia de archivos (MTP)» en la notificación de la barra de estado.
6
Aceptar huella RSA: En la pantalla del móvil aparecerá una ventana: «¿Permitir depuración USB?». Marca la casilla «Permitir siempre desde este equipo» y pulsa Aceptar.
⚠️ Nota Importante: Si la ventana de autorización no sale de inmediato, desconecta el cable USB, vuelve a conectarlo y ejecuta Comprobar_Movil_Conectado.bat.

3. 🎮 Cómo Probar en Tiempo Real con Unity Remote 5

Unity Remote te permite jugar en la pantalla del móvil al instante sin tener que esperar a compilar un APK:

  1. Descarga e instala gratis la app Unity Remote 5 desde Google Play Store en tu Redmi 15.
  2. Abre la app Unity Remote 5 en el móvil (verás una pantalla azul en espera).
  3. Conecta el móvil al ordenador por cable USB.
  4. En Unity Editor, pulsa el botón Play (▶️).
  5. ¡La pantalla del juego se transmitirá en directo a tu móvil y podrás pilotar el avión tocando la pantalla!

Ya configuramos automáticamente el archivo ProjectSettings/EditorSettings.asset con:

EditorSettings:
  m_UnityRemoteDevice: Any Android Device
  m_UnityRemoteCompression: 0 # JPEG
  m_UnityRemoteResolution: 0  # Normal

4. 🧩 Modificaciones de Código y Arquitectura

Modificamos el juego para que funcione con toques móviles hoy y admita multijugador por Bluetooth en el futuro sin tener que reescribir nada:

A. Interfaz Desacoplada: IPlaneInputProvider.cs

Ubicación: Assets/Scripts/WorldGen/Shmup/Networking/IPlaneInputProvider.cs

Esta interfaz permite que el avión reciba controles de cualquier origen: teclado, pantalla táctil, bot de IA o paquetes de red/bluetooth.

public interface IPlaneInputProvider
{
    Vector2 ReadMovement(); // Retorna la dirección (-1 a 1)
    bool ReadFire();        // Retorna si está disparando
}

B. Controles Táctiles en ShmupPlaneController.cs

Ubicación: Assets/Scripts/WorldGen/Shmup/ShmupPlaneController.cs

  • Arrastre Táctil (Touch Drag): Soporta Touchscreen.current (New Input System) y Input.touches (Legacy). Mover el dedo por la pantalla desplaza el avión suavemente.
  • Auto-Disparo Táctil (autoFireOnTouch = true): Mientras mantienes el dedo en la pantalla, el avión dispara automáticamente ráfagas continuas al estilo arcade.
  • Inyección de Input (SetInputProvider): Permite desconectar el teclado local y conectar el receptor Bluetooth cuando juegue el Jugador 2.

C. Puente Multijugador: BluetoothMultiplayerBridge.cs

Ubicación: Assets/Scripts/WorldGen/Shmup/Networking/BluetoothMultiplayerBridge.cs

Define la estructura compacta PlaneNetworkPacket para enviar por Bluetooth:

[System.Serializable]
public struct PlaneNetworkPacket
{
    public int sequenceNumber;
    public float moveX;
    public float moveY;
    public bool isFiring;
    public float posX;
    public float posY;
    public float facingAngle;
    public long timestamp;
}

D. Ventana de Control en Unity Editor

Ubicación: Assets/Scripts/WorldGen/Editor/MobileDeviceManagerWindow.cs

Accede desde la barra superior de Unity en: Tools > 📱 Conexión Móvil y Android > Panel de Control Móvil.

  • Escanear móviles ADB en tiempo real.
  • Reiniciar el servidor ADB si se cuelga.
  • Verificar estado de Unity Remote.
  • Activar depuración inalámbrica por Wi-Fi (adb tcpip 5555).

5. 📡 Hoja de Ruta para el Futuro Multijugador por Bluetooth

Cuando decidas implementar el multijugador por Bluetooth, el flujo de trabajo ya está preparado:

  1. Avión 1 (Jugador Local / Host): Utiliza el input local (táctil o teclado) y el BluetoothMultiplayerBridge.GenerateLocalPacket() empaqueta los datos para enviarlos por el socket Bluetooth.
  2. Avión 2 (Jugador Remoto / Cliente): Se le asigna el BluetoothMultiplayerBridge mediante plane2.SetInputProvider(bridge). Cada vez que llegue un byte por Bluetooth, bridge.FeedNetworkPacket(packet) moverá el segundo avión en tiempo real.
  3. Cero Latencia de Arquitectura: Como el controlador del avión ya está desacoplado, no habrá problemas de conflictos de input ni necesidad de reescribir la física del avión.
